1. Scope & Objectives

Story goal: Allow a user to sign in to VWO using Passkey or Single Sign-On (SSO), in addition to the existing authentication methods, for more secure and convenient access.

Objective: Assess the new login options' visibility, expected success and failure outcomes, compatibility, accessibility/responsiveness, and security properties against KAN-4. Pass requires agreed acceptance criteria to be met in the designated staging environment; staging deployment is stated in the ticket's Definition of Done.

In scope:

  • Visibility and ordering of both buttons below "Sign in with Google".
  • SSO success, invalid-credential handling, and operation with configured identity providers.
  • Successful login with a registered passkey, no-passkey guidance/fallback, passkey failure, and unsupported browser/device messaging.
  • Responsive/accessibility checks requested by the ticket, plus the stated secure-protocol and sensitive-data protections.

Out of scope: Passkey registration (explicitly assigned to a separate story) and SSO provider configuration. Existing login methods are included only for targeted regression around the changed login page; broader authentication regression scope needs confirmation.

Acceptance-criteria identifiers used for traceability:

  • AC-1 - UI: Both named options are visible on the login page below Google sign-in.
  • AC-2 - SSO: Valid SSO authenticates and redirects to the dashboard; invalid credentials show an appropriate error.
  • AC-3 - Passkey: A registered, verified passkey authenticates and redirects to the dashboard; no passkey produces fallback or guidance.
  • AC-4 - Errors: Failed SSO, passkey failure, and unsupported browser/device conditions show appropriate messages.
  • AC-5 - Compatibility: Passkeys work on supported browsers/devices; SSO works with all configured identity providers.
  • AC-6 - Security: Flows use secure protocols (OAuth/SAML/WebAuthn); sensitive data is not exposed in UI or network logs.
  • TS-1..TS-7 - Ticket-listed scenarios: Visibility/order, SSO success/failure, passkey success/no passkey, unsupported platforms, and responsive/accessibility checks.
